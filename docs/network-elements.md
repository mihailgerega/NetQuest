# Элементы сети

Этот документ описывает узлы и каналы связи, которые используются в NetQuest. Все элементы существуют только внутри виртуальной topology и не влияют на настоящую сеть компьютера.

## Client

**Что это:** источник DNS Lookup, Ping или HTTPS-запроса.

**Что можно менять:** IP-адрес, подсеть, шлюз по умолчанию, состояние `healthy/degraded/down`, таблицу маршрутов.

**Как влияет:** если клиент выключен или не знает gateway до другой подсети, симуляция не сможет построить route.

**Пример:** выберите Client-2 в верхней панели и запустите Ping от его имени.

## Server

**Что это:** конечный сервер приложения или цель Ping.

**Что можно менять:** IP-адрес, порт сервиса, имя сертификата, состояние узла.

**Как влияет:** HTTPS проходит только к серверу с reachable path, активным состоянием и подходящим портом.

**Пример:** выключите Server-1 и проверьте, будет ли выбран Server-2 или Server-3.

## DNS

**Что это:** виртуальный DNS-сервер с A-записями.

**Что можно менять:** домен, A value, IP-адрес DNS-узла и состояние.

**Как влияет:** неверная запись может отправить запрос на неправильный узел, а выключенный DNS ломает lookup.

**Пример:** добавьте `api.netquest.local -> 10.0.2.10`, если HTTPS должен идти через Load Balancer.

## Router

**Что это:** узел маршрутизации между подсетями.

**Что можно менять:** таблицу маршрутов, gateway, interface, cost и состояние.

**Как влияет:** route lookup выбирает активный путь. Ошибка в gateway или down-link приводит к `route.not_found`.

**Пример:** добавьте default route `0.0.0.0/0` через reachable gateway.

## Firewall

**Что это:** узел, который разрешает или запрещает трафик.

**Что можно менять:** правила allow/deny, порядок правил, протокол, порт, источник и назначение.

**Как влияет:** первое подходящее правило определяет, пройдёт ли пакет дальше.

**Пример:** разрешите `tcp/443` от Client к Load Balancer и запретите прямой доступ к Server.

## Load Balancer

**Что это:** балансировщик, который выбирает сервер из пула.

**Что можно менять:** алгоритм выбора, автообнаружение, список серверов, weight и enabled.

**Как влияет:** down, disabled, stale и unreachable серверы исключаются. Timeline показывает выбранный сервер и причины пропуска остальных.

**Пример:** добавьте Server-3 в пул, выключите Server-1 и запустите HTTPS failover.

## Link

**Что это:** канал связи между двумя узлами.

**Что можно менять:** состояние, `latencyMs`, `packetLossPercent`.

**Как влияет:** выключенный канал удаляет участок из route, задержка увеличивает виртуальное время, а потеря пакетов может вызвать повторную попытку или ошибку.

**Пример:** увеличьте задержку link к Server-2 до 200 ms и сравните `totalLatencyMs` до и после.

## Canvas

**Что это:** рабочее поле, где пользователь собирает topology.

**Что можно менять:** положение узлов, связи, масштаб, центрирование и выбранный элемент.

**Как влияет:** перед simulation frontend сохраняет текущую topology, и backend рассчитывает результат по свежей версии.

**Пример:** после загрузки упражнения нажмите «По размеру», чтобы увидеть все узлы.

## Ограничения demo-версии

- NetQuest не моделирует настоящие TCP-пакеты и TLS-рукопожатие на уровне байтов.
- BGP, OSPF, Kubernetes и multi-user collaboration не реализованы.
- Симуляция детерминированная и учебная: она объясняет причинно-следственные связи, а не заменяет production network tools.
